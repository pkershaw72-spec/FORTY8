# Forty8 — specification

### What we are building
**Forty8** is an agentic pipeline that takes a broker submission for a natural catastrophe property risk (a Schedule of Values spreadsheet plus a policy slip) and produces a model-ready exposure set, runs it through a catastrophe model, and sends the loss results to a pricing tool. Today this takes about 48 hours of analyst effort; the target is about 48 minutes for straight-through cases.

Owner: AXA XL Catastrophe Modelling. Audience for the first version: internal proof of concept.

### Principles
1. **Agents do the routine, analysts handle exceptions.** Every agent either passes its output on or raises an exception to a human review queue with a clear reason.
2. **Everything is auditable.** Every agent decision is written to an append-only audit log: timestamp, agent, input reference, decision, confidence, rule or model used.
3. **Every external system sits behind an interface.** Build mock implementations first; real connectors are swapped in later via config.
4. **No real client data.** Use synthetic test data only, generated by the repo itself.
5. **Learning loop.** Analyst corrections are stored and reused, so the same exception is handled automatically next time.

### Pipeline (11 steps plus a parallel slip lane)
| # | Agent | Does | Passes when | Exception path |
|---|---|---|---|---|
| 1 | Intake | Accepts SoV (xlsx/csv, multiple tabs) and slip (pdf/docx). Detects language (English, Spanish, others). No ESS template required. | Files parse | Unreadable file → review queue |
| 2 | Cleaning | Removes title rows above headers, subtotal rows and blank rows; combines all worksheet tabs into one table; keeps row lineage (tab, original row). | Clean table produced | Ambiguous header row → review |
| 2b | Contract (slip lane, runs in parallel) | Reads the slip and codes terms: limits, deductibles, perils, sublimits, dates. Each term gets a confidence score. | Overall slip confidence ≥ 85% | < 85% → analyst reviews flagged terms; corrections are stored as learned mappings and the slip is re-scored |
| 3 | Schema mapping | Maps source headers (any language) to the target schema. | All required columns mapped | Unmapped required column → review |
| 4 | Coding | Maps free-text occupancy and construction (any language) to model codes using rules and lookup tables. | Rule match | No rule match → step 5 |
| 5 | ML classification | Classifies the remaining values with a confidence score. | Confidence ≥ configurable threshold | Below threshold → review |
| 6 | Geocoding | Moody's geocoder first for all locations; Bing only for those not at rooftop; agent then searches the web to resolve remaining poor addresses. Check: ≥ 80% of TIV at street level or better. | TIV check passes | Still < 80% → analyst as last resort, prioritised by TIV |
| 7 | Enrichment | Fills COPE gaps from 3rd-party building data; attaches hazard data (NATHAN, Athenium, H3 cell IDs); applies verified engineering survey data; compares with the prior year's submission and fills fields missing this year. Every value records its source. | Completeness score reported | Large year-on-year changes flagged |
| 8 | Audit gate | Runs data quality tests (TIV reconciles to SoV, year built in range, ≥ 80% TIV at street level, construction vs storeys plausible, no duplicates). | All tests pass | Any failure → review, fix, re-test |
| 9 | Policy mapping | Applies coded slip terms to locations, including sublimits by zone. Waits for the slip lane to finish. | Terms on all locations | Missing term → review |
| 10 | Model and track | Submits to the cat model and tracks the job to completion. | Results returned | Job failure or timeout → retry, then review |
| 11 | Pricing | Sends loss metrics (AAL, OEP at 100 and 250 years) to the pricing tool. | Accepted | Rejected → review |

### Connectors (interface + mock for each)
Moody's geocoder and cat model, Bing geocoder, web search, 3rd-party building data, NATHAN, Athenium, H3 (use the real open-source `h3` library), engineering survey store, prior-year submission store, pricing tool, LLM provider (Claude via the Anthropic SDK, for slip reading, header mapping and free-text coding).

### Target schema
Use the Open Exposure Data (OED) location and account format as the target schema unless told otherwise. Keep the mapping layer configurable so a Moody's RMS format can be added.

### What "done" looks like for v1
- `forty8 run <sov> <slip>` processes a synthetic submission end to end against mocks.
- A review queue (CLI or simple web page) where an analyst can see exceptions, correct them, and resume the run.
- The audit log is viewable per run.
- A synthetic data generator produces messy SoVs (title rows, subtotals, multiple tabs, a Spanish tab, missing fields) and slips with deliberately ambiguous wording, so every exception path can be exercised.
- Tests for each agent, plus an end-to-end test that runs a clean case straight through and a messy case that triggers each exception path.
- Run metrics: elapsed time per step, straight-through yes/no, number of analyst touches.

### Suggested stack (change if you have a better reason)
Python 3.12, Pydantic models for every agent's input and output, a simple orchestrator (explicit state machine; no heavy agent framework unless justified), SQLite for runs, audit log, review queue and learned mappings, pytest, and FastAPI plus a minimal HTML page for the review queue.
